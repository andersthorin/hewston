# Story 9.1: API Client Configuration and Feature Flags

**Epic**: Epic 9 — Frontend BFF Integration
**Priority**: High
**Effort**: 1-2 days
**Dependencies**: Epic 8 (BFF Implementation) - Complete ✅
**Status**: Ready for Development

## User Story

As a **developer**,  
I want **configurable API endpoints with feature flags for BFF vs backend selection**,  
So that **I can safely migrate from direct backend calls to BFF endpoints with instant rollback capability**.

## Story Context

### Existing System Integration

- **Integrates with**: Frontend API client (`frontend/src/services/api.ts`), Vite development server, environment configuration
- **Technology**: React + TypeScript, Vite proxy configuration, environment variables
- **Follows pattern**: Existing frontend API patterns and configuration management
- **Touch points**: `frontend/src/constants.ts`, `frontend/src/utils/api.ts`, `vite.config.ts`, environment files

### Business Context

This story establishes the foundation for safe BFF migration by implementing feature flags that allow endpoint-by-endpoint migration with instant rollback capability. This ensures zero risk to existing functionality while enabling gradual adoption of BFF benefits.

## Acceptance Criteria

### Functional Requirements

1. **Environment Configuration**
   - Environment variables control BFF vs backend endpoint selection
   - Support for `VITE_BFF_ENABLED`, `VITE_BFF_CHART_DATA_ENABLED`, `VITE_BFF_RUN_DATA_ENABLED`, `VITE_BFF_WEBSOCKET_ENABLED` flags
   - Default configuration maintains existing direct backend behavior
   - Configuration changes take effect without application restart in development

2. **API Client Updates**
   - Update `frontend/src/constants.ts` to support dynamic API base URLs
   - Implement feature flag logic in API utilities
   - Maintain existing API client interface for component compatibility
   - Support gradual migration of individual endpoint groups

3. **Vite Proxy Configuration**
   - Update `vite.config.ts` to route BFF calls to port 8001
   - Maintain existing backend proxy routes for rollback capability
   - Support both BFF and direct backend routing simultaneously
   - Proper CORS and WebSocket proxy configuration for BFF

### Integration Requirements

4. **Existing Functionality Preservation**
   - All existing API calls continue to work unchanged when flags are disabled
   - No breaking changes to component interfaces or data contracts
   - Existing error handling patterns maintained
   - Performance characteristics preserved for direct backend calls

5. **Feature Flag Implementation**
   - Runtime feature flag evaluation in API client
   - Granular control over different endpoint groups
   - Feature flag status visible in browser development tools
   - Environment-based and runtime toggle capability

### Quality Requirements

6. **Testing and Validation**
   - Unit tests for feature flag logic and API client configuration
   - Integration tests for both BFF and direct backend modes
   - Environment configuration validation
   - Rollback testing to ensure instant reversion capability
