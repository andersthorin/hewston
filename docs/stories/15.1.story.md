# Story 15.1 — Frontend: Non‑navigating create + status badges + gated View

Epic: E15 — Backtests List UX: Background Execution and Inline Metrics
Type: Feature
Status: Draft v0.1

## User Story
As a user, when I start a backtest from /backtests I want to stay on the list, see its status progress (Queued → Running → Done/Error), and only get a View button once it’s finished, so I can continue working without losing context and avoid opening an empty detail page.

## Acceptance Criteria
- Create flow
  - After successful POST /api/v1/backtests, do NOT navigate to /backtests/{id}.
  - The list invalidates and shows the new run row within 2s (polling in place).
- Status badges
  - Render badges: Queued (QUEUED), Running (RUNNING), Done (DONE/COMPLETED), Error (ERROR/FAILED).
  - Badges have accessible text and sufficient color contrast.
- Gated actions
  - The View button is hidden/disabled for non‑terminal statuses; visible/enabled only when status ∈ {DONE, COMPLETED, ERROR, FAILED} (configurable list).
- Polling behavior
  - While any listed run is non‑terminal, the list continues polling at ~2s; stops automatically when all are terminal.
- Optional completion toast
  - When a run finishes while visible in the list, show a toast with a View link (optional, behind a UI flag).

## Notes & Constraints
- Maintain existing filters/pagination; inserting a new row must not disrupt sort order (default -created_at).
- Keep the current “Engine: Nautilus Trader” badge logic for terminal runs.
- Use feature flag(s) if necessary to rollout the non‑navigating create.

## Definition of Done
- Manual flow: create from /backtests → row appears with Queued/Running → becomes Done/Error → View available.
- Tests pass; accessibility checks for badge contrast and text.
- No regressions in existing list filtering/pagination.
