# Story 15.2 — BFF: List enrichment with summary metrics for terminal runs

Epic: E15 — Backtests List UX: Background Execution and Inline Metrics
Type: Feature
Status: Draft v0.1

## User Story
As a user, I want the /api/v1/backtests list to include key summary metrics for finished runs so the UI can render them inline without separate per-row calls.

## Acceptance Criteria
- Enrichment behavior
  - For items in the current page with status ∈ {DONE, COMPLETED}, fetch backend GET /backtests/{id}/metrics and extract fields: total_return, max_drawdown, win_rate, sharpe_ratio (if present).
  - Do NOT fan out for non-terminal items; skip enrichment for QUEUED/RUNNING.
  - If a metrics fetch fails (404/500), record no metrics for that item and proceed.
- Performance & safety
  - Bound the fan-out to the page size (default 20); perform concurrent fetches with sensible limit (e.g., 4–6 in flight).
  - Add short-TTL in-memory cache (e.g., 60–300s) keyed by backtest_id to avoid repeat reads.
  - Behind a feature flag (bff listMetricsEnabled) default ON in dev, OFF in prod until verified.
- Response shape
  - Preserve existing normalized shape; add optional fields on each item: total_return, max_drawdown, win_rate, sharpe_ratio.
  - Return meta.backend_calls including the number of backend requests performed.

## Notes & Constraints
- Reuse existing backend endpoint /backtests/{id}/metrics (reads metrics.json artifact written by the job).
- Do not alter the backend list SQL or schema; this remains a BFF-only enhancement.

## Tasks
1) Update bff/api/backtests.py (list_backtests): for terminal items on the page, concurrently fetch /backtests/{id}/metrics and merge extracted fields.
2) Add simple in-memory cache in bff/services/cache.py or within handler; add feature flag via config.
3) Add unit tests (mock backend responses: ok, 404, 500) and integration test for first-page enrichment.
4) Update runData.ts Zod schema (already includes optional fields) — verify no changes needed.

## Definition of Done
- List endpoint returns metrics fields for completed runs; unchanged for running/queued.
- p50 latency for page size 20 with 10 terminal runs enriched remains acceptable (< 250–350 ms in dev).
- Tests green; feature flag documented with default and override.
