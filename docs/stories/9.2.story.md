# Story 9.2: Frontend Component Migration

**Epic**: Epic 9 — Frontend BFF Integration
**Priority**: High
**Effort**: 2-3 days
**Dependencies**: Story 9.1 (API Client Configuration and Feature Flags)
**Status**: Ready for Development

## User Story

As a **trader**,  
I want **faster chart loading and simplified data operations through BFF aggregated endpoints**,  
So that **I can analyze market data more efficiently with improved performance and reduced loading states**.

## Story Context

### Existing System Integration

- **Integrates with**: React chart components, run detail views, data transformation logic, TanStack Query
- **Technology**: React + TypeScript, Zod validation, existing chart libraries, data visualization components
- **Follows pattern**: Existing React component patterns, data fetching hooks, error handling
- **Touch points**: Chart components, run detail components, data transformation utilities, TypeScript types

### Business Context

This story migrates frontend components to use BFF's aggregated endpoints, reducing complexity by moving data transformation logic to the BFF layer. This delivers the core value of Epic 9: simplified frontend code and improved performance through data aggregation and caching.

## Acceptance Criteria

### Functional Requirements

1. **Chart Data Migration**
   - Chart components use BFF `/api/v1/chart-data` endpoint instead of multiple `/bars/*` calls
   - Single API call replaces multiple backend requests for different timeframes
   - Data decimation and transformation logic removed from frontend (handled by BFF)
   - Chart loading performance improved through BFF caching and aggregation

2. **Run Data Migration**
   - Run detail components use BFF `/api/v1/runs/{id}/complete` endpoint
   - Single aggregated request replaces multiple calls for run details, metrics, and equity data
   - Loading states simplified from multiple concurrent requests to single request
   - Error handling updated for aggregated response format

3. **Data Transformation Simplification**
   - Remove client-side data transformation logic (moved to BFF)
   - Update TypeScript types for BFF response formats
   - Simplify component data processing logic
   - Maintain existing component interfaces and user experience

### Integration Requirements

4. **Component Interface Preservation**
   - Existing component props and interfaces remain unchanged
   - No changes to component usage patterns or parent component integration
   - Existing error handling and loading state patterns maintained
   - User experience identical to direct backend implementation

5. **Feature Flag Integration**
   - Components respect feature flags from Story 9.1 for gradual migration
   - Ability to toggle between BFF and direct backend per endpoint group
   - Graceful fallback to direct backend when BFF unavailable
   - Development tools show which endpoints are using BFF vs backend

### Quality Requirements

6. **Performance and Reliability**
   - Chart loading time improved compared to direct backend calls
   - Run detail loading time reduced through single aggregated request
   - Error handling covers both BFF-specific and backend-passthrough errors
   - Comprehensive testing validates both BFF and direct backend modes

## Dev Notes

### Relevant Source Tree Information
- **Chart Components**: `frontend/src/components/charts/` - Chart visualization components
- **Run Detail Components**: `frontend/src/components/runs/` - Run detail and analysis views
- **Data Hooks**: `frontend/src/hooks/` - Data fetching and state management hooks
- **API Services**: `frontend/src/services/api.ts` - API client functions
- **Types**: `frontend/src/types/` - TypeScript type definitions

### Important Integration Points
- **Chart Data Endpoints**: Currently uses `/bars/daily`, `/bars/minute`, `/bars/hour`
- **Run Data Endpoints**: Currently uses `/backtests/{id}`, `/backtests/{id}/metrics`, `/backtests/{id}/equity`
- **BFF Endpoints**: `/api/v1/chart-data`, `/api/v1/runs/{id}/complete`
- **Data Transformation**: Client-side decimation and formatting logic to be removed

### Critical Requirements
- Component interfaces must remain unchanged for backward compatibility
- Feature flags must control BFF vs backend endpoint selection
- Performance must improve or maintain current characteristics
- Error handling must cover both BFF and backend scenarios

### BFF Response Format Changes
- **Chart Data**: Unified response with metadata (cache status, load time, decimation info)
- **Run Data**: Aggregated response combining run details, metrics, and equity data
- **Error Responses**: BFF may wrap backend errors with additional context
- **Caching**: BFF responses include cache metadata for debugging

### Testing Standards
- **Test Location**: `frontend/src/tests/components/` and `frontend/src/tests/hooks/`
- **Testing Framework**: Vitest + React Testing Library
- **Test Patterns**: Component testing, hook testing, integration testing
- **Coverage Requirements**: 90%+ coverage for modified components and hooks
- **Performance Testing**: Measure and compare loading times for BFF vs backend
