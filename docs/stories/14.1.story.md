# Story 14.1 — Python services: repo‑wide lint/format/type/test/security gates (backend + bff)

Status: Draft
Epic: Epic 14 — Repository‑wide Code Quality Gates & CI Hardening
Owner: PO → Dev

## Goal
Stand up strict yet pragmatic quality gates for Python services (backend, bff): Ruff lint + import order, Black format, MyPy type checks, PyTest with coverage threshold, Bandit security scan, pip‑audit.

## Scope (In)
- Shared configs at repo root: ruff.toml, pyproject.toml (Black), mypy.ini, pytest.ini, .coveragerc
- Pre‑commit with ruff/black/mypy/bandit (+ optional pytest)
- GitHub Actions: matrix over {backend,bff} and Python {3.11,3.12}

## Constraints
- Non‑invasive: no API changes
- Coverage threshold initially 85% (per‑service configurable)
- Reasonable defaults (ignore missing imports to reduce false positives initially)

## Acceptance Criteria
- CI job fails if: ruff, black --check, mypy, pytest --cov-fail-under=85, bandit, or pip‑audit fails
- Local dev can run the same gates with one command (documented in CONTRIBUTING.md)
- Pre‑commit hooks run ruff/black (+ optional mypy/bandit)

## Validation & Tests
- Green CI on main with gates enabled for both backend and bff
- Introduce an intentional lint error in a branch → CI blocks PR

## Implementation Notes
- Use actions/setup-python with pip cache
- Install tooling via pip in workflow (does not modify project requirements)
- Keep mypy strict‑ish but allow ignore_missing_imports initially
