# Story 10.2 — Strategy Framework & Multiple Strategy Support

**Story ID**: S10.2  
**Epic ID**: E10  
**Status**: Ready

## User Story
As a **trading strategy developer**,  
I want **a pluggable strategy architecture that supports multiple trading strategies**,  
So that **I can easily add new AI-powered strategies without modifying core backtesting infrastructure**.

## Context
Second story of Epic 10. Builds on real Nautilus engine (S10.1) to create a flexible strategy framework. This enables multiple strategies and prepares for AI agent integration while maintaining existing parameter handling.

## Technical Implementation Notes

### Strategy Framework Architecture
```python
class StrategyFactory:
    def create_strategy(self, strategy_id: str, params: Dict[str, Any]) -> NautilusStrategy
    
class StrategyRegistry:
    def register(self, strategy_id: str, strategy_class: Type[NautilusStrategy])
    def get_strategy_class(self, strategy_id: str) -> Type[NautilusStrategy]
```

### Strategy Implementation Pattern
- Each strategy inherits from Nautilus Strategy base class
- Parameters validated and configured during instantiation
- Strategy logic implemented in Nautilus framework methods
- Consistent error handling and logging

## Strategy Specifications

### SMA Crossover Strategy
- **Parameters**: `fast` (int, default: 20), `slow` (int, default: 50)
- **Logic**: Buy when fast SMA > slow SMA, sell when fast SMA < slow SMA
- **Validation**: fast < slow, both > 0

### Momentum Strategy  
- **Parameters**: `lookback` (int, default: 14), `threshold` (float, default: 0.02)
- **Logic**: Buy when price momentum > threshold, sell when < -threshold
- **Validation**: lookback > 0, threshold > 0

### Mean Reversion Strategy
- **Parameters**: `rsi_period` (int, default: 14), `oversold` (int, default: 30), `overbought` (int, default: 70)
- **Logic**: Buy when RSI < oversold, sell when RSI > overbought
- **Validation**: 0 < oversold < overbought < 100, rsi_period > 0
