# Story 15.3 — Frontend: Render inline metrics on /backtests with formatting

Epic: E15 — Backtests List UX: Background Execution and Inline Metrics
Type: Feature
Status: Draft v0.1

## User Story
As a user, I want to see the essential performance metrics for each completed backtest directly in the list so I can triage results quickly without opening the detail page.

## Acceptance Criteria
- Columns
  - Add columns: Total Return, Max Drawdown, Sharpe, Win Rate.
  - Values render only when present; otherwise show “—”.
  - Formatting: Total Return & Max Drawdown as percentages with sign; Win Rate as percentage; Sharpe with 2 decimals.
  - Visual cues: negative values use a subdued/warn color; positive returns use a success color (respect theme).
- Status-aware
  - While status is QUEUED/RUNNING, metrics cells render placeholders; once terminal, show values (from list payload).
- Accessibility
  - Include titles/tooltips with metric definitions (link to docs/metrics/run-metrics-definitions.md).

## Notes & Constraints
- Do not fetch metrics per row in the table; rely on BFF-enriched list fields.
- Ensure table remains horizontally scrollable/responsive on smaller widths.

## Tasks
1) Update BacktestsTable row rendering: add four metrics columns with formatting and placeholders.
2) Add unit tests for formatting and status-aware rendering; integration test that uses enriched list payload.
3) Add small legend or tooltips referencing metrics definitions.

## Definition of Done
- Completed runs display metrics with correct formatting; active runs show placeholders.
- No additional network calls from the table for metrics.
- Tests pass; lint/style clean.
