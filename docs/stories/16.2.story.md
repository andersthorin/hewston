# Story 16.2 — Backend: propose_plan Endpoint

Goal
- Implement POST /agentic/propose_plan to return a plan: universe, strategies, params, guardrail pre-checks.

Why
- The UI (and later start endpoint) needs a validated plan before execution.

Acceptance Criteria
- Input: {from_date, to_date}
- Output: {plan_id, universe{included,excluded{reason}}, strategies[], params, guardrails{checks}}
- Uses Epic 18 discovery and Epic 19 guardrail logic
- Errors include actionable messages

Tasks
- Controller + schema validation
- Service: build plan using discovery + defaults
- Guardrail pre-checks and reason codes
- Persist plan (temp store) keyed by plan_id
- Unit tests

Dependencies
- Epic 18, Epic 19
