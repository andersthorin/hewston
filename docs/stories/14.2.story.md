# Story 14.2 — Frontend (Vite/TS/React): lint/format/type/test gates + CI

Status: Draft
Epic: Epic 14 — Repository‑wide Code Quality Gates & CI Hardening
Owner: PO → Dev

## Goal
Enforce readability/maintainability for the Vite/TypeScript/React frontend using ESLint (flat config), Prettier (check), TypeScript type‑check, Vitest coverage, and build verification in CI.

## Scope (In)
- Ensure ESLint covers services/hooks/utils/store in addition to components/views
- Add Prettier config and ignore files; 
- CI: run lint (components/containers/views + services/hooks/utils/store), type‑check, build, tests with coverage, optional Prettier check

## Constraints
- No runtime behavior changes; CI/tooling only
- Prettier check step may require adding Prettier to devDependencies in a follow‑up PR

## Acceptance Criteria
- CI fails on ESLint errors, TypeScript errors, or failing tests
- Coverage is generated; threshold enforcement can be added when agreed
- Optional Prettier check present (skips gracefully if Prettier not installed)

## Validation & Tests
- CI passes on main; introduce a failing lint in a branch → CI blocks

## Implementation Notes
- Keep existing flat ESLint config; broaden CI to include `npm run lint:services`
- Use `vitest --coverage` in CI; thresholds to be added in config later if desired
