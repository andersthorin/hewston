# Story 13.2 — Backend: Streamer attaches cumulative metrics during playback

Status: Approved for Dev
Epic: Epic 13 — Relevant Backtest Metrics with Playback
Owner: Dev (hand‑off from PO)

## Goal
For each emitted playback frame, attach the latest cumulative metrics at or before frame.ts, derived from the precomputed `metrics_path` artifact.

## Scope (In)
- Inputs: `metrics_path` JSON from Story 13.1; equity/frames from artifacts
- Behavior:
  - Lookup‑only: no heavy computation during streaming
  - Attach `metrics` object to each frame with:
    - `return`, `realized_pnl`, `total_return`, `drawdown`, `sharpe`, `win_rate`
- Outputs: WS/SSE frames include an additive `metrics` object (optional)

## Constraints
- Backwards compatible: clients that ignore `metrics` continue to function
- No sorting/filtering requirements in FE
- Deterministic ordering and values across runs and replays

## Acceptance Criteria
- For a finished run, frames contain `metrics` aligned to timestamp with step‑function semantics (hold last seen value)
- Missing data yields `null` values for the respective fields, not errors
- Latency budget maintained (no perceptible increase); no additional frame drops due to metrics attachment

## Validation & Tests
- Integration: a sample run produces frames where `metrics` values match the corresponding points in `metrics_path`
- Negative tests: missing `metrics_path` yields frames without `metrics`, or metrics with `null` values; streamer remains stable

## Non‑Goals (Out)
- Rolling/windowed metrics computation during streaming
- Changes to list endpoints or DB schema

## Implementation Notes (informative)
- Build an index for `[ts_iso -> metrics]` or keep two parallel arrays `[epoch, metrics]` with binary search
- Ensure JSON payload sizes remain small; keep `metrics` scalar
