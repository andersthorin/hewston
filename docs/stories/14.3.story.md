# Story 14.3 — Developer ergonomics & documentation for quality gates

Status: Draft
Epic: Epic 14 — Repository‑wide Code Quality Gates & CI Hardening
Owner: PO → Dev

## Goal
Provide a consistent developer experience with documented one‑shot commands, pre‑commit hooks, and naming/folder guidance aligned with repo conventions.

## Scope (In)
- Add `.pre-commit-config.yaml` and basic repo‑wide configs (.prettierrc, .prettierignore)
- Document local commands and conventions in CONTRIBUTING.md
- Clarify naming & structure guidelines: Python (PEP8; modules by domain), TypeScript (PascalCase components, camelCase vars, kebab‑case filenames except React components)

## Constraints
- No API or runtime changes

## Acceptance Criteria
- Pre‑commit install documented; hooks run locally
- CONTRIBUTING.md includes a “Quality Gates” section with scripts and expectations
- Naming/folder guidance present and consistent with current tree

## Validation & Tests
- Dev can run pre‑commit and local checks successfully

## Implementation Notes
- Keep guidance pragmatic; avoid blocking teams on stylistic minutiae
