# Story 11.2 — Backend Frame Metrics (Nautilus) & Metrics Panel Integration (v1)

Epic: E11 — Streaming Metrics & Synchronized Playback
Type: Feature
Status: Draft v0.1

## User Story
As a user, I want the metrics panel to update continuously during playback using backend/Nautilus-computed metrics so that values are authoritative and consistent with catalogs and reports.

## Acceptance Criteria
- WS/SSE frames include `metrics` object per timestamp (computed by Nautilus-compatible backend code)
- Metrics panel renders total_return_so_far, max_drawdown_so_far, sharpe_so_far (or subset provided)
- No frontend recomputation of financial metrics (formatting only)
- Metrics update per frame and remain synchronized with chart and timeline

## Backend Tasks
1) Extend `produce_frames` or equivalent path to emit metrics per frame using Nautilus outputs
2) For finished runs, compute from artifacts using Nautilus formulas/code paths
3) For in-progress runs, source metrics from runner-side taps or incremental calculators (Nautilus)
4) Update API docs/specs; ensure BFF proxies the shape unchanged

## Frontend Tasks
1) Extend streaming schema/types to include `metrics`
2) Update WS Worker pass-through to keep metrics in frames
3) Update Metrics panel to subscribe to Playback Clock and render streaming values
4) Add graceful fallback if a metric is absent (show em-dash)

## Definition of Done
- Frames carry backend-provided metrics; UI displays them without local computation
- Sync verified via clock instrumentation; acceptance criteria met
