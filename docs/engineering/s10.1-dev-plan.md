# S10.1 Dev Plan — Core Nautilus Engine Integration (MVP)

Epic: E10 — Nautilus Trader Full Implementation  
Scope: Real Nautilus backtesting; SMA strategy; PnL + win rate; preserve artifacts & interfaces

## Overview
This plan breaks S10.1 into concrete dev tasks with targets, acceptance checks, and a small risk spike for Apple Silicon.

## Work Items (A–E)

### A) Data Adapter & Instrument/BarType (Target: 4–6h)
- Add `backend/adapters/nautilus_data.py`
  - `class ParquetDataAdapter`
    - `load_bars(dataset_id: str, from_date: str|None, to_date: str|None) -> pl.DataFrame`
    - `convert_to_nautilus(bars_df: pl.DataFrame, instrument_id: str) -> list[Bar]`
    - `create_data_engine(bars: list[Bar]) -> DataEngine`
- Map dataset_id→instrument_id as `SYMBOL.XNAS` (MVP)
- Normalize timestamps to UTC; validate monotonic order; required columns: t|ts,o,h,l,c,v
- Acceptance:
  - Unit tests pass for UTC normalization, filtering, and conversion

### B) Strategy Framework (SMA) (Target: 4–6h)
- Add `backend/strategies/strategy_factory.py`
  - `class StrategyRegistry`
  - `class StrategyFactory`
- Add `backend/strategies/sma.py`
  - `class SMAStrategy` (Nautilus-compatible)
  - Params: `fast:int`, `slow:int` with validation `fast < slow`
- Register `sma_crossover`
- Acceptance:
  - Unit tests create SMA via factory; invalid params corrected/rejected as per spec

### C) Nautilus Runner Integration (Target: 6–8h)
- Update `backend/adapters/nautilus.py` (replace stub internals; preserve signature)
  - Use `ParquetDataAdapter` to load/convert bars
  - Build strategy via `StrategyFactory`
  - Configure and run BacktestEngine
  - Collect results and format artifacts (orders/fills/equity), compute metrics
  - Respect `HEWSTON_USE_NAUTILUS_STUB` feature flag
- Acceptance:
  - `make backtest` produces artifacts; service/API unaffected

### D) Metrics (PnL + Win Rate) (Target: 4–6h)
- Add `backend/metrics/standard.py`
  - `class MetricsCalculator`
  - `class StandardMetricsCalculator` with PnL & win rate
- Source of truth: engine results (equity curve + fills)
- Acceptance:
  - Unit tests for PnL/win_rate edge cases (no trades, single trade, multiple)

### E) Tests & Perf (Target: 2–4h)
- Add `tests/backend/test_nautilus_integration_mvp.py`
  - End-to-end: derives/loads dataset fixture, runs runner, asserts artifacts existence and keys
- Performance smoke: time 1-year AAPL backtest ≤ 30s on M1 with minimal logging (best-effort)

## Risk Spike: Apple Silicon & Dependencies (Target: 2–4h)
- Goal: Validate `nautilus-trader` installation on M1 with Python 3.11
- Proposed commands (ask before running):
  - `uv add nautilus-trader==0.10.*` (or `pip install nautilus-trader==0.10.*`)
  - Ensure `pandas`, `pyarrow` present (if not, add)
- Outcome: Document exact versions; update lock files; note any build flags

## File/Module Layout (Proposed)
- backend/
  - adapters/
    - nautilus.py                 # BacktestRunner impl (real engine)
    - nautilus_data.py            # ParquetDataAdapter
  - strategies/
    - strategy_factory.py         # Registry + Factory
    - sma.py                      # SMAStrategy
  - metrics/
    - standard.py                 # MetricsCalculator (PnL, win_rate)
  - jobs/
    - run_backtest.py             # Already persists artifacts; unchanged interface

## Acceptance Checks (recap)
- BacktestRunnerPort signature unchanged
- `make backtest` works; artifacts written to data/backtests/<run_id>
- metrics.json contains `total_return` and `win_rate`
- Feature flag fallback to stub operational
- Tests (unit + integration) pass in CI

## Dev Notes
- Keep UTC throughout; avoid tz conversions in loops
- Use Polars for IO; convert to pandas only for Nautilus wrangler
- Apply slippage_bps/fee_bps via simple constants in runner (configurable)

## Next Steps After S10.1
- S10.2: Register more strategies (momentum, mean-reversion) — reuses framework
- S10.3: Add Sharpe, max drawdown; consider DB schema changes in a migration
